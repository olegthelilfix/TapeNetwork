# tape-streamer — HLS видео-стриминг сервис

Самописный сервис для нарезки и раздачи видео по HLS протоколу. Смотрит в папку с видео-файлами, при первом запросе нарезает файл на HLS-сегменты через FFmpeg, кэширует результат и отдаёт клиенту по HTTP.

## Что это

Сервис решает одну задачу: взять обычный видеофайл (mp4, mkv, avi) и отдать его браузеру через адаптивный HLS-стрим с несколькими качествами.

Процесс:
1. Клиент запрашивает мастер-плейлист для конкретного файла.
2. Сервис проверяет, есть ли уже нарезанные сегменты в кэше.
3. Если нет — запускает FFmpeg, нарезает файл на `.ts`-сегменты в нескольких качествах и генерирует `.m3u8`-плейлисты.
4. Сохраняет результат в кэш-директорию.
5. Отдаёт сегменты и плейлисты клиенту.

При повторном запросе отдача идёт напрямую из кэша без перекодирования.

## API

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| `GET` | `/health` | Проверка здоровья сервиса. Возвращает `200 OK`. |
| `GET` | `/videos` | Список доступных видеофайлов в `VIDEOS_DIR`. |
| `GET` | `/stream/{name}/master.m3u8` | Мастер-плейлист с вариантами качества для файла `{name}`. |
| `GET` | `/stream/{name}/{quality}/index.m3u8` | Плейлист сегментов для конкретного качества (`360p`, `720p`, `1080p`). |
| `GET` | `/stream/{name}/{quality}/seg-{n}.ts` | Отдельный `.ts`-сегмент с номером `{n}`. |

## Переменные окружения

| Переменная | По умолчанию | Описание |
|------------|-------------|----------|
| `VIDEOS_DIR` | `/data/videos` | Путь к папке с исходными видеофайлами. |
| `HLS_CACHE_DIR` | `/data/hls-cache` | Путь к папке для хранения нарезанных HLS-сегментов. |
| `PORT` | `8082` | Порт, на котором слушает сервис. |
| `SEGMENT_DURATION` | `6` | Длительность одного сегмента в секундах. |
| `CACHE_MAX_AGE` | `24h` | Максимальный возраст записей в кэше. Принимает целое число (секунды) или duration-строку (`24h`, `90m`). Записи старше удаляются автоматически. |
| `CORS_ORIGINS` | `*` | Разрешённые CORS-источники (через запятую). |
| `MAX_CONCURRENT` | `2` | Максимум одновременных процессов FFmpeg. Ограничивает нагрузку на CPU/память. |
| `TRANSCODE_TIMEOUT` | `15m` | Максимальное время транскодирования одного файла. По истечении FFmpeg прерывается (`504`). Принимает секунды или duration-строку. |

## Качества

Сервис генерирует до трёх вариантов качества:

| Качество | Разрешение | Видео-битрейт | Аудио-битрейт |
|----------|-----------|---------------|---------------|
| `360p` | 640×360 | 800 kbps | 96 kbps |
| `720p` | 1280×720 | 2500 kbps | 128 kbps |
| `1080p` | 1920×1080 | 5000 kbps | 192 kbps |

Качества, превышающие разрешение исходного файла, автоматически пропускаются. Например, для видео 720p будут сгенерированы только варианты `360p` и `720p`.

## Запуск локально

Требования: Go 1.23+, FFmpeg в `$PATH`.

```bash
export VIDEOS_DIR=./my-videos
go run .
```

Сервис запустится на `http://localhost:8082`.

## Docker

```bash
docker build -t tape-streamer .
docker run -p 8082:8082 -v /path/to/videos:/data/videos tape-streamer
```

FFmpeg уже включён в образ. Кэш хранится внутри контейнера в `/data/hls-cache` — примонтируйте volume, если хотите сохранять его между перезапусками:

```bash
docker run -p 8082:8082 \
  -v /path/to/videos:/data/videos \
  -v /path/to/cache:/data/hls-cache \
  tape-streamer
```

## Интеграция с сайтом

Пример с [hls.js](https://github.com/video-dev/hls.js):

```html
<video id="player" controls></video>
<script src="https://cdn.jsdelivr.net/npm/hls.js@latest"></script>
<script>
  const video = document.getElementById('player');
  const src = 'http://localhost:8082/stream/video.mp4/master.m3u8';

  if (Hls.isSupported()) {
    const hls = new Hls();
    hls.loadSource(src);
    hls.attachMedia(video);
  } else if (video.canPlayType('application/vnd.apple.mpegurl')) {
    // Safari — нативная поддержка HLS
    video.src = src;
  }
</script>
```

## Очистка кэша

Фоновая горутина запускается при старте сервиса и раз в час проверяет `HLS_CACHE_DIR`. Записи, чей возраст превышает `CACHE_MAX_AGE`, удаляются целиком (все сегменты и плейлисты для данного файла).

Для принудительной очистки — удалите содержимое `HLS_CACHE_DIR` и перезапустите сервис.
